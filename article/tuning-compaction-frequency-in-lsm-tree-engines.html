Tuning Compaction Frequency in LSM-Tree Engines

Log-Structured Merge-tree (LSM-tree) NoSQL databases—such as RocksDB, Apache Cassandra, and ScyllaDB—rely on compaction to merge data files, purge tombstoned entries, and maintain fast read performance. Compaction frequency is controlled by a combination of memory-to-disk flush thresholds, per-level capacity limits, file count triggers, and background I/O allocations. This guide outlines the key engine parameters across both Leveled and Size-Tiered compaction strategies that directly dictate how often compaction runs.

1. Memtable and Flush Triggers

Compaction cycles begin when in-memory writes are persisted to disk as immutable Sorted String Tables (SSTables). Adjusting how often memory flushes directly alters how often compaction is scheduled.

  • Write Buffer Size (write_buffer_size / memtable_total_space_in_mb): Sets the byte capacity of an individual in-memory memtable. Increasing this size allows the database to absorb more writes before flushing, reducing the frequency of initial SSTable creation and subsequent minor compactions.
  • Max Write Buffer Number (max_write_buffer_number): Determines how many memtables can remain in memory before a write stall occurs. A higher number allows bursts of writes to queue up, resulting in batched flushes rather than continuous, fragmented flushes.

2. Leveled Compaction Parameters (LCS)

In Leveled Compaction (common in RocksDB and LevelDB), data is divided into distinct levels (\(L_0, L_1, L_2, \dots\)), with each level having a fixed capacity. Exceeding these capacities immediately triggers a compaction into the next level.

  • Level 0 Compaction Trigger (level0_file_num_compaction_trigger): Sets the exact number of unsorted SSTables allowed in Level 0 (\(L_0\)) before an \(L_0 \to L_1\) compaction is scheduled. Lowering this value makes compactions run more frequently to keep read latencies low, while increasing it reduces write amplification at the cost of read performance.
  • Base Level Target Size (max_bytes_for_level_base): Specifies the maximum aggregate size (in bytes) of Level 1. Once \(L_1\) exceeds this value, a background compaction to \(L_2\) is queued.
  • Level Size Multiplier (max_bytes_for_level_multiplier): Defines the growth factor for subsequent levels (typically \(10\times\)). Level \(N+1\) capacity is computed as \(\text{max\_bytes\_for\_level\_base} \times \text{multiplier}^N\). Changing this multiplier adjusts how often larger, deeper compactions are initiated.
  • Target File Size (target_file_size_base / sstable_size_in_mb): Dictates individual SSTable file sizes within each level. Smaller target sizes produce more files, leading to smaller, more frequent compactions, whereas larger files lead to less frequent, resource-intensive compactions.

3. Size-Tiered Compaction Parameters (STCS)

Size-Tiered Compaction (widely used in Apache Cassandra for write-heavy workloads) groups SSTables into tiers based on file size rather than explicit, sorted levels.

  • Minimum Threshold (min_threshold): Defines the minimum number of SSTables of comparable size that must exist in a single tier before a compaction job executes. Increasing this parameter postpones compaction until more files accumulate, decreasing compaction frequency.
  • Maximum Threshold (max_threshold): Caps the maximum number of SSTables merged in a single operation. If a large backlog builds, this setting breaks the work into multiple smaller compaction runs.
  • Bucket Low and Bucket High (bucket_low / bucket_high): Adjusts the percentage range used to group files of similar size into the same tier. Narrowing these boundaries limits which files qualify for a merge, delaying compaction runs until identical-sized files exist.

4. Time-Window Compaction Parameters (TWCS)

Time-Window Compaction is designed for append-only time-series data, grouping SSTables according to data timestamps.

  • Compaction Window Size (compaction_window_size): Defines the duration of time (e.g., 1 day, 4 hours) represented by a single window.
  • Compaction Window Unit (compaction_window_unit): The unit of measurement (hours, days) for the window. Compactions only occur frequently while a window is actively receiving writes; once a window expires, SSTables inside it are merged once and never compacted again unless explicitly prompted.

5. Throughput and Concurrency Controls

Even if file-count or size thresholds are crossed, engines throttle compaction execution to prevent I/O starvation.

  • Concurrent Compactors (max_background_compactions / concurrent_compactors): Allocates the number of worker threads dedicated to executing compaction routines simultaneously. Allocating fewer threads serializes compaction jobs, effectively slowing their overall frequency.
  • Compaction Throughput Cap (rate_limiter_bytes_per_sec / compaction_throughput_mb_per_sec): Restricts the disk write bandwidth available to compaction tasks. If compaction I/O reaches this ceiling, active compaction slows down and pending compactions are forced into a wait queue regardless of threshold breaches.
